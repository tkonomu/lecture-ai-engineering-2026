## 宿題

基礎に取り組んだ。`app/config.py` の `RAG_TOP_K` だけを5から1に変え、通常のベクトル検索で同じ質問をもう一度実行した。モデル、指示文、資料、検索DBは変えていない。

| 項目 | 変更前（5件） | 変更後（1件） |
|---|---|---|
| 検索語 | `LoRA 固定 学習 QLoRA 加える` | `LoRA QLoRA 固定 学習 第2回` |
| ツール呼び出し | `search_materials` 1回 | `search_materials` 1回 |
| 取得ページ | 第2回p.52・51・60・47・61 | 第2回p.52 |
| 回答・引用 | 重み固定・差分の学習・4bit化。p.51・52を引用 | 同じ要点を説明。p.52だけを引用 |
| 時間（秒） | 4.34 | 3.05 |
| 入力／出力トークン数 | 3,028／185 | 1,193／223 |
| モデル応答回数 | 2 | 2 |
| 生成API推定費用（USD） | 0.001371 | 0.000915 |

1件でも必要な根拠を取得でき、入力トークンが約61%減った。答えに不要なページを渡さずに済んだ点はよかった。ただし検索語はモデルが決めるため、変更前後で少し違う。時間の差も1回ずつの結果なので、検索件数だけの効果とは言い切れない。

この質問なら1件で十分だったが、複数ページを組み合わせる質問では根拠が足りなくなる可能性がある。件数を減らせばよいと決めず、引用したページで答えを支えられるかを確認したい。

実測した回答、ツールの引数・取得ページ、時間・使用量は [results](results/) に保存した。変更前はコミット `03d0fd3` の `RAG_TOP_K=5`、変更後はこのPRの設定で実行した。
